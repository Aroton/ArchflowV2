# Initialize ArchFlow

Run `archflow-local init` from the repository root. It scaffolds only what `archflow-local review` reads: `.archflow/config.yaml` (reviewer routing), `.archflow/constitution/` (repository policy rules), and `.archflow/.gitignore`. It registers no MCP server and creates no workflow state; the orchestrated workflow is `/archflow-run`, which keeps its state in `.archflow/runs/` and git. Translate the result into a short, conversational summary: what was initialized, what was cleaned up, anything that needs the human, and the next action. Explain failures in plain language with the safe recovery action. When it refuses because a scaffold file diverged from the shipped template, name the file and offer the two choices: keep the human's version (review or delete it, then re-run) or replace every diverged scaffold file with the template via `archflow-local init --force`; run the forced form only when the human chooses it, since it also resets `.archflow/config.yaml`. A repository an earlier ArchFlow initialized usually refuses this way at one of its scaffold files (often `.archflow/config.yaml` or a shipped constitution file), because the shipped templates have changed since. Init removes the legacy registrations before it scaffolds, so the refusal still comes after that cleanup: init writes a line on stderr for each registration it removed or left alone, and you report those alongside the choice. Tell the human that the old `config.yaml` keeps working for review as it is (review ignores the keys it no longer uses), so keeping it is a safe choice; `--force` refreshes every diverged scaffold file to the current templates, which resets `config.yaml` (dropping customized routes) and the shipped default rules, while `constitution/custom/` is preserved.

Defaults live in `constitution/default/`; repository rules and same-ID replacements live in `constitution/custom/`, which force preserves. A flat layout requires explicit forced migration: known shipped filenames are replaced by current defaults and additional numbered rules move to `custom/`. Explain the reported replacements and moves, including that intentional edits in legacy shipped filenames are reset. Existing conflicting custom files are never overwritten. Review reads the configuration and constitution from the working tree, so the next review uses whatever is there; committing them makes the policy shared. Do not relay raw output or expose IDs, digests, JSON, internal managed-policy paths, or protocol codes unless the user explicitly asks for diagnostics or audit detail.

Earlier versions of init registered an `archflow` MCP server that ran `archflow-mcp`, which no longer exists. Init now removes exactly those registrations inside the repository: the `archflow` entry in `.mcp.json` whose command is `archflow-mcp` (deleting the file when nothing else remains in it) and the block between `# >>> archflow managed MCP server >>>` and `# <<< archflow managed MCP server <<<` in `.codex/config.toml` (deleting the file when nothing else remains). Tell the human what was removed. When it reports a registration it left alone (an `archflow` server with a different command, a file it could not read, markers that do not pair up, or a file or `.codex` directory that is a symbolic link, which init never follows), say what was found and that init did not write it, so it stays; edit it only if the human asks. Init never reads or changes anything outside the repository. Other leftovers from the retired task workflow, such as `.archflow/workflow.yaml`, `.archflow/hazards.yaml`, or `.archflow/tasks/`, are no longer read by anything; mention them when present and leave their removal to the human. Older inits also appended `.archflow/** -text merge=binary` to the root `.gitattributes`; init no longer manages that file, and the line makes git merge `/archflow-run` notes as binary, so when it is present tell the human it can be removed and leave the edit to them.

Diagnostics report the Node version, a preflight of each reviewer CLI (Claude and Codex: version, authentication, managed policy), and generated ArchFlow files hidden by an ancestor ignore rule. Init never edits the project root `.gitignore`; ask the human to review that rule and explicitly add only the intended files. Init registers nothing with Claude Code, Codex, or Antigravity, so do not claim it crossed a host's human approval/trust boundary. Do not describe ArchFlow's best-effort dispatch context hygiene as an enforced isolation boundary. If `archflow-local` is unavailable, tell the human it needs reinstalling with `./install.sh` and do not infer initialization from files.

The init command creates no commit. Invoking this skill authorizes scaffolding the shipped defaults, removing the legacy registrations init reports, and committing the resulting repository files without another approval; the skill performs that commit after successful initialization. Inspect and stage only the scaffolded policy files and the registration files init removed or edited, preserving unrelated index and worktree changes. Commit them with `Archflow: Initialize Repository` when there are changes; do not create an empty commit. Summarize the policy defaults, cleanup, diagnostics, and commit. This requested adoption does not authorize overwriting custom policy or installing a machine-global bundle.

When the human asks about reviewer routing, explain the `roles` and `producers` sections of `.archflow/config.yaml` conversationally and point at the commented example in `assets/config.template.yaml` as the reference shape.
