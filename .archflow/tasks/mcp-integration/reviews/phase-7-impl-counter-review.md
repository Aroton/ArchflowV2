# Phase 7 Implementation Counter-Review

1. **minor — `validateDurableSemantics` accepts non-enumerable subject slots and document shell fields despite the success criterion requiring own enumerable data descriptors.** `ownDataSlot` and `ownDataField` in `src/contracts/durable.ts:87-104` check only that `Object.getOwnPropertyDescriptor(...)` returns a data descriptor (`"value" in descriptor`); neither checks `descriptor.enumerable`. Consequently a non-enumerable `state`, `artifact`, or `maintenance` slot, or a non-enumerable canonical-document `value` or `digest`, proceeds normally instead of throwing `TypeError`, contrary to the explicit success criterion in the phase design. The semantic corpus covers enumerable accessors but has no non-enumerable data-property case, so the deviation remains green. **Suggested resolution:** either require `descriptor.enumerable === true` in both helpers and add one subject-slot and one shell-field regression case, or—if D12's earlier “own data descriptor” wording was intended to permit non-enumerable fields—remove “enumerable” from the success criterion so the public contract is internally consistent.

2. **minor — the TypeScript `OutputEntry` authority contains 15 union entries rather than the pinned 14, because `RenameRawSymlink` is listed twice.** `src/contracts/durable-primitives.ts:168-182` repeats `RenameRawSymlink` consecutively. This does not widen the accepted TypeScript shape set, which is why typecheck and the runtime matrices pass, but it silently violates the design's “14 leaf aliases, unioned in pinned order” transcription and makes the TypeScript authority no longer a one-for-one representation of the JSON Schema and Zod ladders. **Suggested resolution:** remove the duplicate union member and keep the union in the exact 1–14 table order.

No blocker or major finding was identified. The pinned `(rank, sub-rank, slot, collection path, index)` evaluation order and error carriers in `validateDurableSemantics` otherwise match the invariant table, including the rank-2 guard that prevents `STATE_INVALID` from throwing on an undecodable state phase. The seven new schemas also use the pinned cross-chunk `$def` owners without re-declaring another chunk's target, and the JSON Schema and Zod OutputEntry authorities contain all 14 unique branches with the specified required/forbidden fields.

## Triage

Triaged 2026-07-28. Both findings were reproduced against shipped source before disposition. **One accepted, one rejected.**

| # | Severity | Disposition | Resolution |
|---|---|---|---|
| 1 | minor | **accepted** | Reproduced. `ownDataSlot` and `ownDataField` (`src/contracts/durable.ts:87-104`) checked only `"value" in descriptor`, so a non-enumerable data slot or shell field passed, contrary to the success criterion's "own **enumerable** data descriptor". Took the tighten branch rather than the loosen-the-criterion branch, because the repository has already settled this question in the same direction: `assertPlainJson` rejects a non-enumerable property *inside* a value as "not a JSON value" (`plain-json.ts:85`). Leaving the shell weaker than the check applied to the shell's own contents would be the inconsistency, not the criterion. The concrete hazard is also real and distinct from the accessor cases: `canonicalJsonBytes` serializes only enumerable properties, so a non-enumerable `value` or `digest` is invisible to the very digest the validator re-derives. Both helpers now require `descriptor.enumerable`, the reason is recorded at the call site, and five regression cases were added to `test/contracts/durable-semantics-corpus.test.ts` (three subject slots, two shell fields). No sanctioned caller is affected — `canonicalDocument` builds from an object literal (`canonical.ts:104`), so its properties are enumerable. |
| 2 | minor | **rejected — does not reproduce** | `src/contracts/durable-primitives.ts:168-182` declares the `OutputEntry` union with **exactly 14 members in pinned order 1–14, none repeated**. `RenameRawSymlink` occurs twice in the file only as its type declaration (`:149`) and its single union member (`:180`); `sort \| uniq -d` over the union block returns nothing and the member count is 14. The TypeScript authority is already a one-for-one representation of the JSON Schema and Zod ladders, which the reviewer's own closing paragraph independently confirms for those two. No change made. |
