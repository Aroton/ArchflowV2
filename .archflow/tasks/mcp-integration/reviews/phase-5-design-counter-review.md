# Phase 5 Design Counter-Review

1. **Blocker — the `fast-uri` security gate covers only one of four current high-severity advisories and names an obsolete safe floor.** The current SDK source map identifies embedded `fast-uri@3.1.0`, and the measured release build contributes the enclosing `ajvProvider-CEoC__sr.mjs` chunk. The design checks only [GHSA-q3j6-qgpj-74h6](https://github.com/advisories/GHSA-q3j6-qgpj-74h6), fixed in `3.1.1`. The same embedded version is also affected by [GHSA-v39h-62p7-jpjc](https://github.com/advisories/GHSA-v39h-62p7-jpjc), fixed in `3.1.2`; [GHSA-4c8g-83qw-93j6](https://github.com/advisories/GHSA-4c8g-83qw-93j6), fixed in `3.1.3`; and [GHSA-v2hh-gcrm-f6hx](https://github.com/advisories/GHSA-v2hh-gcrm-f6hx), fixed in `3.1.4`. All four advisories say there is no workaround. Registry evidence shows `3.1.4` is the current safe 3.x release and `4.1.1` is latest overall. `@modelcontextprotocol/server@2.0.0` is current and still embeds `3.1.0`, so no patched MCP artifact presently exists. A review or risk acceptance that addresses only the named advisory could authorize a payload still affected by three undisposed vulnerabilities. **Suggested resolution:** make the implementation-start gate perform a current advisory sweep for every embedded component, enumerate all four `fast-uri` advisories, and require at least `3.1.4` for a 3.x replacement. Until a patched MCP artifact exists, stop for a separate explicit prototype-risk decision that names all four advisories and binds the focused inert-runtime reachability analysis; never treat `3.1.1` as resolved.

2. **Major — the tracked-write path can promote a self-authenticating stage without mandatory independent reproduction.** `checkReleasePayload` makes `comparisonRoot` optional, and the tracked writer is described as validating an external stage before copying it. A stage produced from tampered `node_modules` can consistently describe and hash its own altered bundle, metafile, and legal receipt. The clean-root `npm ci` reproduction is a separate verification activity, so the write command can acquire tracked authority before that independent check runs. Esbuild's [metafile contract](https://esbuild.github.io/api/#metafile) reports build inputs and outputs, not every resolution-controlling read or proof that installed bytes came from the lock tarballs. **Suggested resolution:** require `write-tracked-release` to consume a validated independent-reproduction receipt (or perform materialization, `npm ci`, rebuild, and byte comparison itself) before replacing tracked output. Bind and verify resolution-controlling package manifests and exact tarball identities as part of that proof; keep comparison optional only for read-only checking.

3. **Major — `release/legal-review.json` has no strict structural/version authority.** It is a trust-bearing machine-readable format, but the only new schema is `release-manifest.schema.json`; the design simultaneously says that schema is solely the manifest shape authority and that `validateReleaseSemantics` is not a second shape model. This leaves no owner for the receipt's version, closed keys, field types, `current_components`, or `dependency_gate_decisions`, contrary to REQ-04's strict versioning requirement. **Suggested resolution:** add and register a strict versioned legal-review schema, or place its complete closed shape in an anchored `$defs` section of the release-manifest schema and compile that exact subschema against the external receipt before semantic correlation. Include unknown-key rejection and exact current/history record variants.

4. **Major — dependency-owned legal/provenance inputs fall outside the clean-root verification contract.** Post-`npm ci` verification covers only dependency-owned `bundle_inputs`. The actual esbuild metafile includes the SDK's contributing `.mjs` chunk but not its adjacent `.mjs.map`, package manifests, or license files. Those omitted files are exactly what the design needs to discover embedded versions, registry/tarball provenance, and applicable texts. A clean root can therefore validate every dependency bundle input while deriving legal evidence from unbound installed files. **Suggested resolution:** add a closed dependency-owned provenance/control collection for every source map, package manifest, license/notice file, and other evidence input. Record path, byte count, and digest in the manifest and verify all of them after `npm ci` before legal derivation, rebuilding, or comparison.

5. **Major — the claimed exact embedded-component closure is not derivable from the specified outer metafile/map evidence.** Esbuild attributes final bytes to prebundled SDK chunks, not to the packages embedded inside them. The current contributing AJV provider map names sources from `ajv@8.18.0`, `ajv-formats@3.0.1`, `fast-uri@3.1.0`, `fast-deep-equal@3.1.3`, and `json-schema-traverse@1.0.0`; other contributing SDK maps add further nested roots such as `content-type@1.0.5`. These versions differ from or are absent from the npm lock graph. Binding an outer chunk and adjacent map does not establish which mapped sources survived the second esbuild pass, and 17 mapped AJV JSON sources have empty `sourcesContent`. The document nevertheless claims exact physical contribution and graph closure. **Suggested resolution:** define a general exhaustive adjacent-map discovery and nested component-mapping contract for every contributing prebundle; pin the known Phase 5 closure, tarball integrities, licenses, and retained texts; distinguish embedded from installed same-name versions; and fail on unrecognized roots or missing maps. Either add composed-range/fingerprint evidence tying final output to embedded sources or conservatively inventory all mapped components and narrow the claim from exact physical contribution. Preserve the empty-AJV-JSON limitation explicitly instead of combining it with an unqualified exactness claim.

6. **Major — the exact schema and asset coverage is undefined.** The architecture requires schema/asset bindings and CI failure on their drift, but the phase repeatedly refers only to "declared schema/assets." The current release metafile contains eight JSON schemas and no `assets/**`, while the repository contains a larger schema and shipped-asset set. Separate chunks could reasonably choose embedded-only files, all v1 schemas, or all shipped assets and each believe it implements the design. **Suggested resolution:** enumerate the exact v1 schema and asset namespaces or paths covered in this phase, state which are bundle inputs versus release controls, and define how non-bundled shipped members enter or intentionally do not enter the offline payload.

7. **Major — the proof harness and protocol fixtures are not required to be manifest-bound.** The control list names build/check/write/materializer scripts but omits `scripts/smoke-release-bundle.mjs`, `scripts/test-release-integrity.mjs`, `test/fixtures/release/hostile-runtime-guard.cjs`, the release integration test, and the existing byte-exact MCP runtime fixtures. The guard is the sole non-payload executable in the hostile run, yet weakening it or a transcript need not cause manifest drift, conflicting with the architecture's requirement that CI fail on protocol-fixture drift. **Suggested resolution:** define a closed digest-bound proof-input subset containing the complete smoke/mutation harness, guard, CI command wiring, and exact transcript fixtures, and mutation-test omission, substitution, and stale digests.

8. **Major — the JavaScript guard cannot support the universal "no network connection or listener" claim.** The build accepts every `node:` external, while the closed interception list omits `node:dns`/`node:dns/promises`, `dns.Resolver`, Node's WebSocket/EventSource/Undici entry points, and child-process- or worker-mediated networking. Patching selected public JS methods is not equivalent to running without network capability. **Suggested resolution:** for the inert Phase 5 payload, reject every builtin outside a pinned measured allowlist (currently the bundle reports only `node:process`, `node:buffer`, `node:util`, and `node:crypto`, plus the banner's `node:module`) and add negative DNS/WebSocket fixtures. If the claim remains universal, add OS/syscall-level network denial or observation and retain the JS guard only as a diagnostic oracle; otherwise narrow the success criterion to the exact guarded surfaces.

9. **Major — hostile-copy launch isolation is underspecified and the existing integration convention would violate it.** The phase does not pin the child's `cwd`, inherited environment, `HOME`/cache locations, or Node bootstrap variables. Existing `mcp-stdio.test.ts` launches its temporary bundle with the repository root as `cwd` and inherits the ambient environment. `NODE_OPTIONS`, `NODE_PATH`, preload/loaders, or repository-relative discovery can therefore add executable/input bytes outside the claimed payload and guard. **Suggested resolution:** require `cwd` inside the isolated hostile copy, an explicit minimal environment with Node preload/module-resolution/package-manager variables removed, controlled nonexistent home/cache paths, direct `process.execPath`, and canaries proving repository-local files/modules are unavailable. Bind this launch profile as a release control.

10. **Major — a `fast-uri` reachability/risk disposition is not bound tightly enough to the code whose risk it evaluates.** The proposed record binds SDK/chunk/map/advisory evidence, but not the exact final bundle, entry/handler authority, or reachability-test digest. A prototype acceptance based on the inert Phase 5 route could remain present when Phase 12 rebuilds the payload with real handlers and new attacker-controlled flows. **Suggested resolution:** bind every current vulnerability disposition to the exact bundle digest, entry set, handler-authority state, reachability evidence digest, and approved prototype scope. Any rebuild, dependency change, or handler-authority change must invalidate it and rerun the gate; a retained historical record must never satisfy the current-payload check.

11. **Major — `dependency_gate_decisions` is called immutable history without an enforceable carry-forward rule.** The checker can prove only that the current receipt and manifest agree. Deleting or editing an old decision and regenerating both can still pass on a fresh checkout, so the promised retention of a superseded `fast-uri@3.1.0` decision is not enforced. **Suggested resolution:** give decisions stable IDs and content digests, require the previously tracked accepted decision set to be a byte-identical subset of every successor, and represent corrections with explicit amendment/supersession records. If no prior-baseline comparison is intended, call this retained current-checkout evidence rather than immutable history.

12. **Major — chunk boundary contracts are too incomplete for this nine-part phase.** `ReleasePayloadSummary` is undefined, `validateReleaseSemantics(...)` has no signature, and `stageManifest` has no pinned type. The design does not fix the validated-stage authority flow, canonical bytes versus parsed values, exact shared exports, or CLI arguments/exit behavior even though builder, checker, writer, materializer, mutation suite, and CI are separate chunks. Divergent implementations can create the second shape/canonicalization authorities the design forbids. **Suggested resolution:** define exact exported signatures and closed argument/return shapes for all shared seams, including canonical manifest bytes, parsed values, validated closed file sets/digests, provenance collections, and CLI flags/stdout/stderr/exit contracts. Leave algorithms to implementation.

13. **Major — path, root-containment, and file-kind safety are not specified strongly enough for the materializer and writer.** Requiring absolute roots and lexical "outside the repository" checks does not reject symlink aliases, a staged symlink, filesystem roots, non-regular files, or an output ancestor redirected into the repository. The existing temporary-build helper is lexical-only, so reusing that pattern would make this concrete. **Suggested resolution:** define one portable repository-relative path codec (`/` separators; no absolute, drive, UNC, backslash, empty, or dot segments), canonical/realpath non-overlap checks, `lstat`-based rejection of symlinks and non-regular files, and new-empty-dedicated-root preconditions for source, stage, comparison, and tracked-write traversal. Mutation-test symlink ancestors and attempts to overwrite pre-existing external files.

14. **Major — CI dependency currency and supply-chain pinning are omitted from a release-integrity phase.** The actual workflow still uses `actions/checkout@v4` and `actions/setup-node@v4`; current official releases are [checkout v6.0.2](https://github.com/actions/checkout/releases/tag/v6.0.2) and [setup-node v6.4.0](https://github.com/actions/setup-node/releases/tag/v6.4.0). Moving major tags are also mutable dependencies, so even updating to `@v6` would not make the release proof reproducible or supply-chain pinned. **Suggested resolution:** review runner compatibility, move to the current supported majors, pin each action to a reviewed full commit SHA with a version comment, and include those identities in the release-control evidence or explicitly scope the reproducibility claim to payload bytes rather than the CI executor.

15. **Minor — tracked-byte reproducibility does not control Git checkout conversion.** `.gitattributes` currently contains only `* text=auto`. Generated `.mjs`, JSON, and legal text may therefore be checked out with CRLF under `core.autocrlf`, while the builder mandates LF and performs byte comparison. Two Ubuntu jobs with default Git settings do not exercise this boundary. **Suggested resolution:** add explicit attributes for `dist/**` and retained legal files (`text eol=lf` for canonical text, or `-text` where exact upstream bytes must be retained) and add a checkout-normalization fixture or mutation test.

## Triage

1. **Accepted.** The design now requires a live advisory sweep for every embedded component, enumerates all four current high-severity `fast-uri@3.1.0` advisories, establishes `3.1.4` as the safe 3.x floor, records that no compatible patched MCP server currently exists, and requires any separate prototype-risk decision to name the complete advisory snapshot and inert reachability result.
2. **Accepted.** `writeTrackedReleasePayload` can no longer promote a candidate stage after self-validation. It must independently materialize source, run `npm ci`, verify installed dependency and provenance bytes, rebuild into another root, and byte-compare the two closed payloads before touching `dist/`.
3. **Accepted.** The design adds and registers a separate strict versioned `release-legal-review.schema.json` for the receipt, current-component, decision, amendment, and supersession shapes; the single semantic validator correlates it with the manifest.
4. **Accepted.** A closed `dependency_provenance_inputs` collection now binds every consulted map, dependency package manifest, retained registry/tarball identity record, and license/notice file by path, size, and digest and re-verifies them after the independent install.
5. **Accepted in part.** The design adopts exhaustive adjacent-map discovery for contributing dependency prebundles, pins the known embedded closure, distinguishes installed from embedded versions, and fails unknown roots or missing expected maps. It deliberately rejects composed source-map/range machinery as disproportionate and narrows the claim to conservative component inventory rather than exact embedded physical-byte attribution; the empty-Ajv-JSON limitation remains explicit.
6. **Accepted.** Declared coverage is now the complete tracked `src/contracts/schemas/v1/*.schema.json` namespace plus `assets/workflow.yaml` and the five exact constitution files. The eight currently bundled schemas are named; every other schema/asset is a release control unless the actual metafile makes it a bundle input.
7. **Accepted.** A closed `proof_inputs` reference set now binds the release smoke/mutation harness, guard, release and stdio integration tests, exact runtime fixtures, package command wiring, and CI workflow. Each physical file still has one bundle/control owner; omission, substitution, or staleness invalidates proof.
8. **Accepted in part.** The design rejects all imports outside the measured inert allowlist (`node:process`, `node:buffer`, `node:util`, `node:crypto`, plus banner `node:module`), rejects dynamic built-in loading, extends guarded globals to `fetch`, `WebSocket`, and `EventSource`, and adds DNS/WebSocket negatives. It rejects a new OS/syscall sandbox as out of scope and narrows the claim to measured imports and declared guarded surfaces rather than universal capability isolation.
9. **Accepted.** The hostile launch profile now fixes a copied-payload cwd, direct `process.execPath`, explicit argv and stdio, a minimal scrubbed environment, controlled unusable HOME/XDG/npm-cache/temp locations, and repository/module canaries; the profile and fixtures are digest-bound.
10. **Accepted.** A current vulnerability disposition now binds the exact bundle digest, entry/role set, `inert-no-handler` authority, complete advisory snapshot, reachability evidence, and prototype scope. Bundle, dependency, handler, or entry changes invalidate it, and Phase 12 must rerun the gate.
11. **Accepted in part.** Decisions now have stable IDs/digests; the tracked writer requires prior accepted decisions to remain a byte-identical subset, and corrections append typed amendment/supersession records. The design calls these retained audit records and does not add a generalized Git-history subsystem.
12. **Accepted.** The interface section now pins canonical document, payload summary, validated stage, and reproduction proof shapes; exact shared function signatures; candidate-to-reproduction authority flow; and CLI flags, stdout/stderr ownership, and exit statuses while leaving algorithms to implementation.
13. **Accepted.** The design adds one portable path codec, canonical realpath non-overlap, filesystem-root rejection, `lstat`-based symlink/non-regular-file rejection, new empty dedicated intermediate roots, and a fixed real-repository `dist/` target with adversarial path/root mutations.
14. **Accepted in principle; proposed versions corrected as stale.** Live official release pages on 2026-07-27 show `actions/checkout@v7.0.1` and `actions/setup-node@v7.0.0`, newer than the review's v6 suggestions. The design pins their reviewed full SHAs (`3d3c42e5aac5ba805825da76410c181273ba90b1` and `820762786026740c76f36085b0efc47a31fe5020`), requires runner-compatibility review, disables package-manager caching for the independent proof, binds workflow/action identities, and scopes reproducibility to payload bytes rather than the hosted executor.
15. **Accepted.** The Files, boundaries, and verification sections now require `.gitattributes` rules that force canonical generated release text to LF while preserving exact upstream legal source bytes as `-text`, with clean-checkout and mutation coverage.
