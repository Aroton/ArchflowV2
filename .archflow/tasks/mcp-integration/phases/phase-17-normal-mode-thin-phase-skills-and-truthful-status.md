# Phase 17: Normal-Mode Thin Phase Skills and Truthful Status

**Status**: DESIGNED
**Task**: mcp-integration
**Goal**: Drive the normal MCP workflow from host-neutral phase skills and report only reconciled durable truth.
**Requirements**: REQ-03, REQ-06, REQ-07, REQ-08, REQ-09, REQ-10, REQ-13, REQ-14, REQ-20, REQ-41

## Context

Phases 1–16 are COMPLETE and the runtime works: five tools, a fourteen-command `archflow-local`, gates that block and resume, a fixed-point evaluator, reconciliation, and an installer. **Nothing drives any of it.** The six non-`init` skills contain zero references to MCP, the five tools, `archflow-local`, `state.json`, gates, or the constitution. They infer phase state from markdown filenames and a `**Status**:` line, hand-write a copy/paste prompt for "the other client", and commit directly. They also use a document layout — `architecture.md`, `phases/phase-1-setup.md` — that `classifyRepositoryPath` does not admit; the canonical layout is `prd.md`, `design.md`, `phases/<n>/design.md`, `phases/<n>/impl-notes.md`.

Being the first phase to actually drive the pipeline end to end, this phase is also the first to hit three shipped defects that no existing test could catch, because every fixed-point test hands both reviews one synthetic fingerprint and stubs the resolver. **(D1) The review fixed point cannot close, at three separate steps.** The declared-input fingerprint is not uniform across the pipeline: `rubricDigest` (`src/state/fingerprint.ts:57-61`) folds in the rubric for `archflow_counter_review` only, and `artifactPaths`/`upstreamPaths` (`src/state/fingerprint-readers.ts:82-102`) fold in artifact identities for counter-review and adjudicate and upstream identities for adjudicate. So (a) self-review evidence carries the `archflow_state` value (`src/state/transitions.ts:131-134`) while counter-review evidence is stamped with the counter-review call's (`src/mcp/handlers/counter-review.ts:112`), and `deriveCurrentEvidenceSet` (`src/state/evidence-results.ts:509`) plus `currentReviewSet`/`currentFor` (`src/review/fixed-point.ts:96-113`) require them equal — so `archflow_state{step:"triage"}` can never succeed and `assessCurrentEvidence` can never report past `self_review`; and (b) even with that fixed, `runAdjudication` throws `"adjudication subject is not durably current"` (`src/review/adjudication.ts:293`) because the adjudicate call's fingerprint carries the upstream identities while durable state holds the `adjudicate/running` value. **(D2) A human cannot resolve a gate in normal mode.** `runDurableGate` polls the task-root `gate.decision` (`src/state/gates.ts:1043`), but the only helper surface, `decide --kind decision`, writes the server's own archive at `decisions/<gate-id>/decision.json` — which in normal mode is worse than useless, since a pre-existing archive makes `createExclusive` return non-`created` and the resolver reports `STATE_INVALID/gate-resolution-race`. And the published `decision_template` (`src/state/gates.ts:214-229`) lists field *names* only, while `parseInterface` (`:267-283`) demands a fully bound `GateDecisionEnvelope`, or the structurally distinct cancellation shape, or the distinct waiver shape. **(D3) The receipt-only orphan is unreachable.** `reconcileCurrentAuthority` emits it only when the receipt digest differs from `state.committed_intent.receipt_digest` (`src/state/reconciliation.ts:126,148`), so a receipt found *by* the committed intent ID is committed by construction and the branch is dead.

**(D4) Normal mode cannot finish a task.** `nextPhase` walks `phase-impl-N → phase-design-(N+1)` and stops only at `Number.MAX_SAFE_INTEGER` (`src/state/transitions.ts:65-74`), and no live normal handler sets `terminal` — the only writers are the checkpoint and initialization-import paths (`src/state/checkpoints.ts:142,160`, `src/state/initialization.ts:154,204`). A `task-complete` status action could therefore only report terminal authority imported from a checkpoint.

Three offline gaps remain besides. Nothing constructs a `document` or `implementation-output` artifact anywhere in `src/`; nothing computes a request digest or gate ID offline, so no skill can print the true gate ID before the blocking call; and `computeDegradedStatus` carries no attempt, fingerprint, gate kind, or next action, verifies no config digest, and performs no reconciliation.

**What the D1 repair costs.** The uniform recipe (below) is not free, and the design does not claim it is. Removing the rubric and the artifact/upstream identities from the fingerprint removes the *only* post-dispatch freshness observation on the counter-review and adjudicate paths: `handleCounterReview` hashes the artifact before dispatch (`src/mcp/handlers/counter-review.ts:61-64,104-114`) and `runCounterReview` does not enter `runStateTransaction` until the child returns (`src/review/counter-review.ts:92-119`), so today an edit during dispatch moves the transaction-time fingerprint and rejects installation. Two of the three bindings relocate cleanly — the rubric to `deriveCurrentEvidenceSet`'s `self.rubric_digest === counter.rubric_digest` (`src/state/evidence-results.ts:511`), and the artifact's *identity* to the server-computed `subject_digest`, which `handleAdjudicate` re-reads and rejects as `STATE_INVALID/adjudication-subject-not-current` (`src/mcp/handlers/adjudicate.ts:93-98`). The third does not: nothing compares a retained adjudication's recorded upstream digests against the currently approved ones (`currentFor`'s adjudicate branch checks only subject, fingerprint, and source-review-set digest, `src/review/fixed-point.ts:124-128`), which REQ-13 explicitly requires. So chunk 1 restores two checks explicitly rather than pretending nothing was lost.

## What We're Building

Four repairs to shipped contracts, a small offline seam, and five rewritten skills. The repairs make the declared-input fingerprint uniform across the four non-produce steps so the fixed point can close — restoring by hand the two freshness checks that uniformity removes — give the human a real way to author `gate.decision`, make the Phase 9 orphan discoverable, and give normal mode a way to finish a task. The seam adds three `archflow-local` commands — `envelope`, `build-document`, `build-implementation-output` — extends `decide` and `validate`, and upgrades `status` from degraded-only to a reconciled normal-mode report that verifies the pinned config digest and derives exactly one next action from the workflow graph, reconciliation findings, and the fixed point.

The five phase skills then become marshallers over one pipeline: read `status`, follow its `next_action`, build the artifact with a command, compute the envelope with a command, call the tool, repeat. Status carries not just an assessment but the exact references the next call needs — the derived `CurrentEvidenceSetRef`, per-slot finding identities, self-review provenance from the pinned config — so triage and gate assembly are transcription rather than computation, and five independently written prompts cannot drift into five different derivations. Skills differ only in phase-specific content: which document, which rubric (REQ-10), which upstreams, which parents, which gates. No skill branches on host identity, names a client, or asks the model which host it is running in.
