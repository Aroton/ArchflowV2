# Phase 10: Adoption, Reconciliation, and Recovery

**Status**: DESIGNED
**Task**: mcp-integration
**Goal**: Adopt valid initial and manual authority into state and recover bounded task truth without promoting prepared or divergent material.
**Requirements**: REQ-04, REQ-08, REQ-13, REQ-14, REQ-21, REQ-22, REQ-23, REQ-24, REQ-26, REQ-39, REQ-50

## Context

Phase 9 established the mature-state, transport-neutral transaction kernel: authenticated repository/task authority, a one-task lock, live state/config reads, closed request binding, revision CAS, immutable write-ahead receipts, exact replay, and state-last atomic commit. That kernel deliberately rejects missing state and delegates legal workflow movement, initialization, checkpoint adoption, and recovery classification to this phase. Phase 8 already supplies strict manual checkpoint/import shapes, chain selection, and consolidated semantic validation, but its continuation model assumes an adopted checkpoint and therefore cannot bootstrap manual checkpoints from an existing ordinary state.

This phase extends those authorities rather than adding a second state model. `state.json` remains the sole normal-mode commit authority: direct initialization, chain adoption, reconciliation, and handoff repair may validate retained evidence, but only a successful state-last transition advances task authority. Context documents were stamped at commit `91a7c95`; current Phase 9 interfaces and the live tree take precedence where they differ.

## What We're Building

Enable the architecture's closed optional `archflow_state.artifact` union and add a workflow-transition planner around Phase 9's transaction seam, plus a sibling revision-0 initialization transaction for the only valid no-state operations: direct normal initialization, direct legacy initialization, or an initial closed checkpoint import whose first checkpoint embeds one of those manifests. Both paths reuse the same authenticated authority, lock, artifact-aware request/receipt identity, immutable receipt installation, atomic state replacement, semantic validator, and ambiguity arbitration. Checkpoint adoption validates and selects a complete initial or continuation chain before one final state write records only its exact head.

Amend the Phase 8 checkpoint contract with an explicit state-anchor branch for the first checkpoint created from ordinary state. The anchor binds the exact canonical state digest and revision; the first checkpoint is its immediate successor, while every later checkpoint continues to name the prior checkpoint revision and digest. State revision and adopted checkpoint revision are independent counters after adoption: a continuation wrapper binds current state through `expected_state_revision`/`expected_state_digest` and separately binds the exact adopted checkpoint through `predecessor`. Add bounded reconciliation over caller-supplied current projections, the request's deterministic intent, and the active gate/checkpoint head, alongside separate caller-bounded audit/repair operations. Complete Git conflict/divergence recovery with immutable preserve-both-heads and clean-handoff evidence while making no merge, commit, push, or distributed-lock claim.

## Work Breakdown

1. **Artifact, checkpoint, and handoff contracts**: Enable `StateInput.artifact?: DurableArtifact` with the existing five-member closed union. Pin the state-operation mapping as `record-state-boundary` when absent and, by artifact kind, `adopt-task-initialization`, `adopt-legacy-import-initialization`, `record-document-artifact`, `record-implementation-output`, or `adopt-manual-checkpoint-import`; each artifact operation binds `{phase_instance, step, status, artifact_kind, artifact_digest}` where `artifact_digest` is recomputed from the one validated/materialized canonical artifact. Extend `ManualCheckpointV1`, `ManualCheckpointImportV1`, and `ChainAnchor` with an explicit state-anchor discriminant carrying `state_revision` and `state_digest`. Require the state-anchored first checkpoint to be the immediate successor of that exact canonical state, to retain its initialization digest, and to appear only when state has no adopted checkpoint; retain the existing `PredecessorLink` contract unchanged after that first checkpoint. Amend continuation semantics so `expected_state_revision` authenticates the current state independently, while `predecessor` authenticates `state.adopted_checkpoint`; remove the existing equality between those two revisions. Define a strict immutable handoff record that binds repository/task identity, both preserved divergent heads, their last common authoritative checkpoint, the explicit human-selected successor, and the later clean observed handoff position without presenting any of them as a distributed lock.

2. **Workflow-transition planning**: Add one transport-neutral planner consumed by transaction preparation. It derives legal phase/step/status movement from the fixed validated workflow, correlates the artifact and current evidence with the actual phase instance and step, and requires the kernel-recomputed input fingerprint before producing a `NextStateDraft`; malformed, stale, or lifecycle-invalid subjects fail before any receipt or state write.

3. **Revision-0 initialization**: Add a sibling to `runStateTransaction` for missing-state authority. Under the authenticated task lock it rereads `state.json`, accepts only revision-sentinel-0 requests carrying the matching initialization operation and artifact, validates a direct normal/legacy initialization or an initial closed chain against live repository, task, config, workflow, constitution, policy-base, and initialization identities, then uses Phase 9's receipt-first/state-last protocol to install revision 1 exactly once. Its receipt records the pinned artifact-derived operation and request digest, so exact replay can resume while reuse with a changed manifest or chain returns `INTENT_MISMATCH`. A concurrently created state, mismatched retry, partial receipt, or ambiguous write follows the same CAS, replay, and durable-reread principles as mature-state transactions.

4. **Whole-chain adoption**: Build an adoption planner for direct initial imports, state-anchored first imports, and checkpoint-predecessor continuation imports. It validates the complete caller-supplied chain, rejects foreign candidates, gaps, forks, mixed anchors, wrong-state anchors, and stale evidence, and derives one successor state whose `adopted_checkpoint` names only the selected head; no intermediate checkpoint becomes state authority and checkpoint files remain caller/manual artifacts rather than server-generated writes. The planner mints a non-exported WeakSet-authenticated adoption capability consumed by `runStateTransaction`; the kernel permits only the exact validated `adopted_checkpoint` change and only with durable receipt operation `adopt-manual-checkpoint-import`, while ordinary preparations keep the existing preservation rule and all repository/task/config/workflow/constitution/policy pins remain immutable. The consolidated prepared/committed validator uses that durable operation discriminant when retained receipts are re-read, preserving rank 8a unchanged for every ordinary receipt rather than accepting a caller-controlled flag.

5. **Bounded reconciliation and explicit audit/repair**: Define an ordinary reconciliation input containing only canonical current state, explicitly supplied current projection digests, the deterministic requested intent/receipt when relevant, and the active gate or checkpoint head. Return closed classifications and exact next actions without scanning retained directories, restoring payloads, or promoting receipts, checkpoints, decisions, or model output. Keep explicit audit/repair separate: it may validate and classify a caller-bounded list of retained paths/documents, but it still cannot infer a winner or advance state; Phase 15 owns directory enumeration and command/handler integration. Include an explicit abandoned-lock repair operation that runs only after separate human confirmation that no task writer is live, re-resolves the fixed `.transaction-lock` direct child under the authenticated task root, rejects symlinks, non-directories, unexpected contents, or a missing/replaced target, and removes only that exact empty directory. It never infers abandonment from age or owner metadata and never performs automatic takeover.

6. **Conflict, divergence, and clean handoff**: Reuse `readHistoryStatus` and `classifyMutationReadiness` to keep Git conflicts, in-progress operations, and divergent histories mutation-blocking. Add a repair/handoff planner and narrow immutable installation for evidence that both heads were preserved, a human selected the successor chain, and a later clean one-writer handoff was observed. It never merges, commits, pushes, removes an abandoned task lock, or claims to detect independent-clone races before histories diverge.

7. **Fault and real-boundary verification**: Pin revision-0 races, receipt-only interruption, whole-chain state-last cuts, state-anchor mismatch, bounded reconciliation, explicit-history limits, semantic error precedence, and handoff collisions in unit and real-process tests. Extend the real-Git matrix for conflicts/divergence and preserve-both-heads repair, and verify paths with spaces/Unicode plus task/symlink isolation through the existing repository fixtures.

## Success Criteria

- [ ] Missing state reaches revision 1 only from a semantically valid direct normal/legacy initialization or an initial closed checkpoint import beginning with one of those manifests, with every pinned identity duplicated into and authenticated by the committed state.
- [ ] `archflow_state` accepts only the closed optional durable artifact union, selects the exact operation literal by artifact kind, and binds the recomputed canonical artifact digest into request identity; same-intent reuse with changed artifact bytes returns `INTENT_MISMATCH` rather than replaying prior success.
- [ ] The revision-0 path preserves Phase 9's lock, CAS, exact-intent replay, receipt-first/state-last commit, and ambiguous-write recovery behavior without adapting the mature-state kernel to pretend state exists.
- [ ] Initial, state-anchored, and continuation checkpoint chains are validated as a whole and adopted with one final state replacement that records the exact head; interruption never exposes partial chain authority.
- [ ] An ordinary state with no adopted checkpoint can anchor its first checkpoint to the exact canonical state revision/digest; wrong-state, forked, gapped, foreign, or mixed-anchor chains fail closed, and every later link remains a checkpoint revision/digest predecessor. Multi-checkpoint adoption advances state once, records the later checkpoint head, and a subsequent continuation authenticates the independent current-state revision/digest plus that exact adopted checkpoint.
- [ ] Workflow transitions reject illegal lifecycle movement and artifacts or evidence bound to the wrong phase instance, step, status, or recomputed input fingerprint before any durable commit.
- [ ] Ordinary reconciliation examines only the explicitly supplied current projections, requested deterministic intent, and active gate/checkpoint head, and reports receipt-only or projection mismatch facts without retained-history scanning or authority promotion.
- [ ] Explicit audit/repair classifies only caller-bounded supplied history and never infers a missing approval, chooses between competing successors, or promotes orphaned preparation.
- [ ] A SIGKILL-abandoned task lock remains blocking until an explicit, separately human-confirmed repair revalidates and removes only the exact empty task-local lock directory; age, metadata, malformed targets, and automatic takeover never authorize removal, after which the exact receipt-only intent can resume with refreshed CAS.
- [ ] Git conflict/divergence stays non-authoritative until immutable evidence records both preserved heads, the human-selected successor, and a clean handoff; no code path auto-merges, commits, pushes, or claims cross-clone exclusion.
- [ ] Contract, unit, crash, integration, typecheck, and temporary-build verification passes, aside from any unchanged previously documented release-integrity failures.
