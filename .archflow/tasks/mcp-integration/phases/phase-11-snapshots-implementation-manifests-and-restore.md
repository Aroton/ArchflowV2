# Phase 11: Snapshots, Implementation Manifests, and Restore

**Status**: DESIGNED
**Task**: mcp-integration
**Goal**: Retain and restore deterministic declared outputs within explicit storage, retention, collision, and secret-safety bounds.
**Requirements**: REQ-08, REQ-11, REQ-13, REQ-21, REQ-22, REQ-23, REQ-25, REQ-26, REQ-33, REQ-39, REQ-50

## Context

Phase 10 completed the transport-neutral transition, initialization, adoption, bounded-reconciliation, and repair seams on top of Phase 9's receipt-first/state-last transaction kernel. Payloads and mutable projections are still absent: a prepared transaction currently installs only its immutable receipt before `state.json`, and reconciliation can report a projection mismatch but cannot authenticate or restore retained bytes. This phase adds that missing storage lifecycle while preserving `state.json` as the sole normal-mode commit authority. A receipt-only retry must reconstruct and reinstall its declared outputs from retained authoritative bytes; it must not rerun untrusted preparation.

Phase 7 supplies the durable vocabulary this work consumes: `OutputEntry`, canonical blob identities and modes, `SnapshotAccountingV1`, `ImplementationOutputV1`, `SecretScanResult`/`SecretScanner`, `MaintenanceRecordV1`, `ProjectionDigestRef`, and `TaskStateV1.authoritative_results`. It deliberately left byte facts, the four implementation identity digests, result-reference resolution, and path-class verification to this phase. The context documents are stamped at `91a7c95`, fourteen commits behind current `5a902ef`; the live contracts, path resolvers, Git runner, transaction code, and Phase 10 handoff take precedence. Phase 12 owns gate lifecycle and applying collision decisions, Phase 15 owns handlers, CLI commands, and directory enumeration, and Phase 17 owns status UX.

## What We're Building

Add a task-local content-addressed result store at `results/sha256/<result-digest>/`. Its strict server-internal `ResultManifestV1` embeds the exact validated `DocumentArtifactV1` or `ImplementationOutputV1`, so `artifact_digest` remains resolvable and Phase 12 can consume the retained implementation evidence. The manifest's canonical digest is the `result_digest`; `snapshot_digest` is amended to mean only the domain-separated declared-output snapshot, never the result address.

The materializer derives all implementation identities from authenticated paths and real Git/index/worktree bytes. It hashes regular files through their path's clean/attribute conversion and symlink targets without conversion. It reuses a Git blob only when `ImplementationOutputV1.base_commit` plus the declared output/rename path proves the exact OID and mode and that commit remains on the current task-branch ancestry; merely naming the commit is not retention. This deliberately limits zero-copy reuse to bytes already addressable in that retained base tree, such as an unchanged blob moved by a pure rename. Adds, modified after-images, rename-with-modification after-images, document projections, index-only objects, and unreferenced loose objects use counted raw payloads.

Projection and restore operate from a complete authenticated plan over declared paths only. They classify every collision before mutation, revalidate the complete before-image immediately before the first write, and compare each target again immediately before its own replacement. State is written last and alone commits a generation. Maintenance uses a small schema-specific walk over caller-supplied roots and cannot authorize deletion from an incomplete inventory.

## Identity Derivations

All four previously structural-only digests use `canonicalJsonDigest` over canonical JSON with an explicit `schema_version: "1"` and `digest_kind`. Arrays are ordinal-sorted and duplicate/conflicting path observations are rejected before hashing.

- **Declared scope** is the sorted union of every `outputs[].path` plus every rename `previous_path`. Snapshot/worktree observations are exactly `{path, path_class, state: "absent"}` or `{path, path_class, state: "present", file_type, mode, size_bytes, oid, content_digest}`. Index observations are exactly `{path, state: "absent"}` or `{path, state: "present", stage: 0, mode, oid}`. Regular-file OIDs use `git hash-object --path=<declared-path> --stdin`; symlink OIDs use `gitBlobOid(targetBytes)` or equivalent `git hash-object --stdin` with no `--path`. `content_digest` is SHA-256 of the exact projected regular bytes or symlink target bytes.
- **`snapshot_digest`** hashes `{schema_version, digest_kind: "declared-output-snapshot", entries}` where `entries` use the exact snapshot observation variants above after applying all declared operations. Deletes and rename sources contribute explicit absent entries. A document contributes one present regular-file entry for `projection_target`, class `document`, mode `100644`, its `byte_count` as `size_bytes`, its `content_digest`, and the independently derived regular-file OID. This amends Phase 7's stale “retained result” comment; `result_digest` alone addresses retained manifests.
- **`diff_digest`** hashes `{schema_version, digest_kind: "implementation-diff", base_commit, entries}` where each sorted entry contains exactly `path`, `path_class`, `operation`, `file_type`, optional `previous_path`, and the declared before/after blob identities. Storage choice, payload accounting, and secret-scan metadata are excluded because changing retention must not change the reviewed diff.
- **`index_identity_digest`** hashes `{schema_version, digest_kind: "declared-index-identity", entries, undeclared_changes}`. `entries` use the exact index observation variants above for every declared-scope path; any nonzero stage fails rather than being normalized away.
- **`worktree_identity_digest`** hashes `{schema_version, digest_kind: "declared-worktree-identity", entries, undeclared_changes}`. `entries` use the exact snapshot/worktree observation variants above for every declared-scope path. Unrelated file bytes are never hashed into either identity; their names/counts appear only through the canonical `UndeclaredChangeReport` the artifact already carries.

The server derives and compares these facts when creating the result. Later reads revalidate the retained artifact digest and all manifest/artifact relations; they do not pretend creation-time index/worktree observations still describe a later checkout.

## Work Breakdown

1. **Pin the retained result contract**: Define `ResultManifestV1` with exactly `schema_version: "1"`, `task_id`, `repository_identity_digest`, `result_id`, `phase_instance`, `step`, `artifact_digest`, `source_artifact: DocumentArtifactV1 | ImplementationOutputV1`, `input_fingerprint`, `snapshot_digest`, `outputs: readonly OutputEntry[]`, `projections: readonly ProjectionDigestRef[]`, `accounting: SnapshotAccountingV1`, and `secret_scan: SecretScanResult`. Require `artifact_digest === canonicalJsonDigest(source_artifact)`, correlate every duplicated fact, and require the manifest path to carry the manifest's canonical `result_digest`. The embedded artifact avoids a new file/path class and retains `diff_digest`, `parent_documents`, `declared_inputs`, base/index/worktree identities, restore targets, and undeclared-change evidence for later gates.

2. **Derive implementation facts and durable restore sources**: Resolve and classify every declared path and both rename endpoints, reject cross-class renames, and derive the four identity subjects above. A rename is non-overwriting: its destination must be absent at derivation, classification, and apply; an existing destination is a collision because Phase 7's shape carries no destination-before identity. Verify add/modify/delete/rename, before/after identities, file type, tree mode, parents, restore targets, accounting, and undeclared-change report. Regular files use path-aware conversion for OIDs; symlinks use unconverted target bytes. Never use `hash-object -w` as retention.

   Select `git-object` for a surviving after-image only when `git merge-base --is-ancestor <base_commit> HEAD` succeeds for the current task branch and `ls-tree`-style verification proves its exact OID/mode at the authenticated output path — or at `previous_path` for a pure rename — in that commit; re-run both proofs on every read/restore. Otherwise use `raw-payload` and count the bytes. Adds and changed after-images therefore use raw storage in the current pre-commit workflow; this phase adds no per-entry alternate-commit proof. Delete's schema-fixed `storage: "git-object"` means only that deletion retains no post-state payload; its `before` bytes may be authenticated either by the current authoritative generation's retained raw payload or by the base-commit/path proof. If neither source exists, deletion is a collision. A missing later proof for an entry that did choose `git-object` is `SNAPSHOT_INVALID`, never a fallback to object existence.

3. **Materialize and authenticate bounded snapshots**: Preflight every output and the complete live task-local copied-byte total against the existing 25 MiB/result and 250 MiB/task caps before creating the result directory. Install raw payloads and the manifest without clobbering an existing content address; identical bytes are reuse, while any digest/path/content disagreement is `SNAPSHOT_INVALID`. An unchanged fingerprint resolves and validates its existing authoritative manifest byte-for-byte; its creation-time `accounting` is not rewritten because task revision or retained-byte totals later changed. Validate stored byte counts/digests, commit reachability for `git-object` entries, projection digests, embedded artifact digest, and every manifest/artifact correlation on read or restore.

4. **Scan before Git-tracked projection**: Pin exact runtime dependencies `@secretlint/core@13.0.4` and `@secretlint/secretlint-rule-preset-recommend@13.0.4`, plus exact development dependency `@secretlint/secretlint-rule-aws@13.0.4` solely to satisfy the preset's shipped declaration under `skipLibCheck: false`. The resulting reviewed lock closure is fourteen packages: twelve MIT and two BSD-2-Clause. Import the preset's public `rules` array, register its creators as top-level rules, and omit `@secretlint/secretlint-rule-filter-comments` entirely; do not use the preset `creator` or a nested `disabled` flag. Derive `detector_set_id` from a canonical, versioned description of the exact pins, sorted enabled rule IDs, omitted filter rule, ID-map version, and byte-transform version.

   Call `lintSource` with `noPhysicFilePath: true`, `maskSecrets: true`, `contentType: "unknown"`, and a fixed non-repository synthetic `filePath`. Strict UTF-8 candidates use their text view; other bytes use a one-byte-to-one-code-unit Latin-1 view. Preserve useful explicit extensions but force `.p12` to `ext: ""`, because the bundled GCP rule reads `source.filePath` directly; document that structured PKCS#12 credentials are not detected. Map only known `@secretlint/secretlint-rule-<suffix>` IDs injectively to `secretlint:<suffix>` and construct fresh findings only from that mapped ID, candidate-owned path/class, and one-based positions. Never spread, serialize, log, or retain upstream message, data, source, or content. Detection or scanner unavailability fails before projection.

5. **Project, restore, and classify collisions**: Build one gate-neutral `ProjectionPlan` that records the exact observed before identity, including absence, for every declared target. An exact current target is reusable. An absent target, or a before-image authenticated by the current authoritative raw payload or a commit-reachable Git object, is restore-ready; a divergent or unavailable before-image yields collision facts and no writes. Rename plans require both an authenticated source and an absent destination and never call overwrite-style rename on an existing target. Represent `discard-and-restore`, `adopt-as-new-generation`, and `abort` for Phase 12 without creating a gate or applying a decision here. Before the first mutation, reread every target and abort with zero writes on any mismatch; immediately before each replacement, compare that target again. A later mid-apply mismatch never overwrites the changed target and uses the already-authenticated rollback plan for prior mutations, yielding prior/next authority or one precise repair. This is cooperative collision protection, not a claim to eliminate hostile filesystem TOCTOU.

6. **Extend producing transitions, transaction resume, and reconciliation**: Pin the public facts as `ResultInstallationPlan { reference: AuthoritativeResultRef; projection_plan: ProjectionPlan }` and the live seam as `PreparedResultTransaction<K> = PreparedTransaction<K> & { result_installation: InternalResultInstallation }`. Before entering the task kernel, `prepareResultInstallation` validates/materializes caller-owned inputs once, stages immutable bytes in memory, and mints a non-exported WeakMap-authenticated capability whose public facts are the `ResultInstallationPlan`; it performs no durable write. The Phase 9 `prepare` callback remains bounded and filesystem-pure while the lock is held: it can only return that already minted capability. `materializePlan` admits the optional fourth slot, authenticates and consumes it once, and `installPlan` revalidates its observed source facts and caps under the task lock before installing payload/manifest/projections, receipt, and state in that order. Ordinary operations retain the exact three-slot `PreparedTransaction<K>`.

   `planStateTransition` accepts the capability's authenticated reference only for a successful result-producing boundary, requires its phase/step/fingerprint and `result_id` to match the correlated transaction result, inserts or replaces the `(phase_instance, step)` entry in canonical order, and rejects any other `authoritative_results` change; ordinary transitions preserve the set exactly. Collision classification reads the current reference before replacement. The transaction requires the exact reference in `next_state` before the first write.

   A receipt without state commits no result. Exact resume selects the reference from the validated receipt's prepared state, reloads the embedded source artifact and retained bytes, reconstructs and revalidates the projection plan against current authority, and installs state without invoking preparation. `reconcileCurrentAuthority` accepts only caller-supplied manifest/projection/collision observations and never promotes orphan results.

7. **Use bounded roots for explicit maintenance**: Avoid a generic reachability abstraction. From validated caller-supplied current state, every supplied validated checkpoint in its chain, supplied resumable receipts' prepared states, and supplied decision/review evidence, collect named result references; load only those manifests; collect only their named payloads. Missing, contradictory, or incomplete roots fail closed, and Phase 15's enumerator must supply/attest the complete inventory before deletion can be authorized. Categorically retain manifests, current generations, checkpoint/decision/review evidence, and receipt-resume bytes. After independently authenticated human approval, write `MaintenanceRecordV1` no-clobber before idempotently deleting only proven `unreferenced-attempt` or `superseded-payload` candidates.

8. **Verify real boundaries with proportional fault cuts**: Add focused contract, unit, integration, and real-process crash coverage for the schema-only manifest, canonical identity producers, Git attributes/modes/symlinks/object pruning, exact cap edges, scanner non-leakage, transition replacement, collision races, receipt-only resume, and authority-moving payload/manifest/projection/receipt/state cuts. For maintenance, one real record-before-delete cut plus one representative deletion cut and ordinary repeated-call idempotence coverage is sufficient; do not build a per-deletion process-kill matrix. Keep MCP handlers, local CLI/enumeration, gate lifecycle/decision application, and status presentation out of this phase.

## Success Criteria

- [ ] An unchanged fingerprint restores byte-identical declared outputs while unrelated tracked/untracked bytes remain untouched; a changed fingerprint creates one retained generation, and a collision changes nothing before an explicit decision.
- [ ] The four canonical digest producers reject forged `diff_digest`, `snapshot_digest`, `index_identity_digest`, and `worktree_identity_digest`; implementation manifests round-trip add/modify/delete/rename, binary data, modes, regular-file attribute conversion, unconverted symlink OIDs, parents, restore targets, and undeclared-change observations.
- [ ] A manifest retains and revalidates its exact source artifact, so Phase 12 can load `diff_digest`, parent documents, declared inputs, and the other implementation evidence without relying on request-lifetime memory.
- [ ] Only output bytes addressable in the retained base tree receive zero-copy `git-object` storage. Adds, changed after-images, document outputs, and index-only objects use counted raw payloads and remain restorable after `git prune --expire=now`; a later deletion may authenticate its before-image from that current authoritative payload.
- [ ] Representative copied-byte growth reaches but never exceeds 25 MiB per result or 250 MiB per task; either excess returns non-advancing `SNAPSHOT_LIMIT`, writes no partial payload/projection, and creates no hidden authority.
- [ ] Every current, checkpoint, decision/review, and resumable-receipt result remains reachable. Human-approved maintenance prunes only the two permitted non-authority categories and cannot break rerun, restore, receipt resume, or checkpoint chains.
- [ ] Secret fixtures fail before projection even when surrounded by broad, line-scoped, or rule-targeted Secretlint disable directives; the filter rule is absent from top-level registration, `.p12` performs no filesystem read, and upstream secret-bearing messages/content never escape the adapter.
- [ ] The result reference reaches `next_state` only on its matching producing transition; receipt-only retry restores retained bytes without a second preparation call.
- [ ] A changed target between classification and apply, or between two path mutations, is never silently overwritten; the transaction leaves prior/next authority or one exact repair.
