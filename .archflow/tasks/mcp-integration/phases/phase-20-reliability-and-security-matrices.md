## Context

Nineteen phases shipped 1,639 tests across 146 files in about fifty seconds, and each owning phase proved its own invariant on a representative case. Phases 17, 18, and 19 each deferred the same three things here: the exhaustive path matrix, the file-kind and fault matrix for snapshots and restore, and the adversarial matrices. This phase is that debt. Most of it is parameterization rather than invention — the two-process race proof, the four two-clone divergence fixtures, the caps at all four boundary corners, the gate attack corpus, and the seventeen-class path partition are already total at their own layer, and the honest Phase 20 outcome for those is citation in the matrix record, not another test.

Three real gaps set the phase's shape, none of which is a missing test alone. First, `src/init/registration.ts` writes `.mcp.json` and `<repo>/.codex/config.toml` with a plain truncating `writeFile` (`:180`, `:295`), so an interrupted registration truncates the user's own host configuration; REQ-01 promises unrelated host configuration is preserved. Second, the server's next action for a pinned-config mismatch is `restore-pinned-config` (`src/state/next-action.ts:126`) and says nothing about a new task or upgrade — that guidance exists only in skill prose, so architecture criterion 4 cannot be met by a test. Third, every caller of every secret-rejection path injects a clean scanner stub: the only `SECRET_DETECTED` reference in the entire suite is an error-construction unit test, so three constructing sites and five propagation paths are dead code as far as the suite knows.

Two seams block the rest. `createProductionServices` hardcodes its `atomic` writer and its `gate_secret_scanner` (`src/state/production.ts:425`, `:432`), which is why all three crash fixtures hand-roll the transaction kernel from thirteen modules and why nothing above it — handlers, local commands, accounting, manual checkpoints — has ever been on a fault path. `stageLegacyUpgrade` constructs its projection writer inline (`src/init/legacy-upgrade.ts:303`), so legacy staging cannot be faulted at all. Both are ordinary composition-root wiring, not fault hooks; `src/state/{atomic,lock,transaction}.ts` are untouched, so the crash-control policy test's source scan is unaffected.

An earlier draft of this design claimed a fourth defect — that server shutdown never aborts in-flight invocations. It was wrong, and the correction matters to the plan. The SDK's `_onclose()` aborts every request-handler controller, our adapter's transport `close` calls `transport.onclose?.()`, and those controllers' signals are exactly `ctx.mcpReq.signal`, which reaches the dispatch child's abort listener and its process-group kill. The chain is complete in shipped code. What remains genuinely unobserved is whether `terminate()` resolves before `terminateChild`'s SIGTERM-to-SIGKILL escalation completes, which for a `detached` child would let it outlive the server. That is an observation to make, not a fix to plan.

## What We're Building

Two small source fixes, two composition-root seams, and one matrix expansion. The fixes are the truncating host-config write and the missing new-task-or-upgrade guidance. The seams make the production services and legacy staging faultable. The expansion adds one shared task-workspace builder and one shared cut-name list, then drives the existing proofs across the dimensions their owning phases deferred: projection writes and manual checkpoints under a real `SIGKILL`, config pinning at every enforcement site, Git blob identity across the configurations where it genuinely must collapse, real secret rejection along every propagation path including under replay, the file-kind matrix for manifest restore, legacy staging faults and collisions, the remaining gate-decision attack arms, and path attacks driven through the handler entry rather than only the resolver.

The phase's other deliverable is honesty about what is not proven. The architecture's own criterion says lack of proof marks a matrix entry unsupported, and the PRD has already accepted six cells as out of reach without OS containment: a child reading the repository, a child reading the real `$HOME` or other-family credentials, managed-context containment, Codex tool-surface emptiness, the sandbox provider, and the `openResolved` TOCTOU window. These are recorded as written limitations, each stating what is not protected and why that is acceptable for a local developer tool. They are deliberately *not* turned into inverted tests that assert a canary is readable — such a test asserts a fact about the operating system rather than about ArchFlow, cannot fail in response to any ArchFlow change, and reads as broken to the next maintainer. The suite already has the one useful control in this family: the leaking-fake negative control that proves the canary *scanner* works. Test the detector, not the absence of containment.

Explicitly not built, because the operating envelope does not pay for it: OS containment or any sandbox provider; a per-config-byte mutation matrix (the pin is one whole-file SHA-256, so variants cannot fail independently — enforcement-*site* coverage is the real gap); a real 250 MiB per-task allocation (slow and flaky, and proves nothing the injected accounting scalar does not); the full Git configuration cross-product, which the architecture already declined; a full initialization-kind × cut cross-product (`runStateInitialization`'s two durable write sites are unconditional and kind-agnostic, and `manual-import.ts` writes nothing atomically, so extra kinds add children without adding failure modes); real managed-policy tests needing root and a real CLI; closing the TOCTOU window; signing decision files; entropy heuristics in the canary scanner; a proven-cell inventory duplicating what the suite already is; and any new MCP tool, gate kind, error code, runtime dependency, durable schema field, or workflow-graph change. No new test framework, matrix runner, or fault-injection subsystem is introduced — the crash mechanism stays substitute-the-writer-and-`SIGKILL`, and each crash child keeps its own private kill helper, because the three vocabularies are disjoint sets over materially different control flows and a shared helper would need more modes than the lines it replaces.

## Work Breakdown

1. **One task workspace, and cut lists that are authoritative where they live.** Extract the six-step repository-plus-task recipe duplicated across the Phase 15, 17, 18, and 19 suites into `test/helpers/task-workspace.ts`, exporting `createTaskWorkspace(options)` returning the workspace, its production services, and a disposer. `patterns.md` §8 records that test helpers know nothing about `src/`, with `resolved-constitution.ts` as the one deliberate exception — this becomes the second, so carry the same explicit header saying it deliberately builds a real capability from `src/`, keeping the rule legible. Adopt it in new tests and migrate an existing suite only where a later chunk already edits it; do not rewrite suites this phase does not otherwise touch.

   Do **not** add a separate global cut-name list. A hand-maintained list consumed by a negative bundle scan is not authoritative — a future fixture can declare a cut and omit the list, and the scan still passes. Instead have each crash child export the cut list it already declares and validate its own requested cut against that list, so declaration and exercise are the same source of truth; the bundle scan then imports the three children and scans for the union. That also removes the phase-12 child's substring fall-through, where an unrecognized action silently does nothing.

2. **Two seams and two source fixes.** Export `ProductionInput` from `src/state/production.ts` with optional `atomic` and `gate_secret_scanner` fields defaulting to `createAtomicWriter()` and `createSecretlintScanner()`, and add an optional `projection_writer` to `StageLegacyUpgradeInput`. Add `projection_writer` to `ProductionInput` only if a chunk below actually consumes it; an unconsumed override is not worth shipping. Give `src/init/registration.ts` its own small temp-write, `fsync`, `rename` helper — the branded `AtomicWriter.replace` accepts only `task-state` and `gate-interface` path classes and `ProjectionWriter.replaceRegular` only PROJECTABLE ones, and host-config files have no path class, so widening either allowlist is the wrong trade and would edit a file the crash-control policy test scans. Scope the claim honestly: `registerClaudeProject` shells out to `claude mcp add`, which writes `.mcp.json` itself, so this covers ArchFlow's own re-serialization write. Finally, extend the `restore-pinned-config` rationale in `src/state/next-action.ts` to state that a changed pinned config requires a new task or the explicit upgrade flow.

3. **Observe dispatch lifecycle before changing anything.** Write the observations first and let them decide whether source changes here are needed at all: shut the server down with a dispatch in flight, inject a `notifications/cancelled` frame, and add a heartbeat grandchild to prove the process-group kill reaps descendants that remain in the group. The abort chain from `_onclose()` through `ctx.mcpReq.signal` to `terminateChild` already exists, so the expected result is that the child and its in-group grandchild are reaped and the invariant is recorded as already satisfied. If a survivor does appear, the likely cause is `terminate()` resolving before the SIGTERM-to-SIGKILL escalation completes for a `detached` child — raise that at the gate as a scoped follow-up rather than absorbing an unplanned redesign.

   Then close the descendant-*escape* cell, which Phase 20's scope names explicitly and which the architecture already records as unproven. A descendant that calls `setsid()` leaves the adopted process group and survives the group kill by construction. Make that observation once, bounded and cleaned up, during implementation — do not ship it as a permanent test, for the same reason no test asserts a canary is readable: it would assert an operating-system fact that no ArchFlow change can alter. ## Success Criteria

- [ ] Every crash cut leaves the committed prior or next state, or a precise non-advancing repair; prepared receipts, results, and projections are never authority. Projection writes and manual checkpoints are cut for the first time, and no cut point is declared without being exercised.
- [ ] Each crash child validates its requested cut against the list it exports, and the bundle scan derives its cut names from those same lists and covers both shipped bundles, so declaring a cut and guarding it are one source of truth.
- [ ] `PINNED_CONFIG_MISMATCH` is proven at every enforcement site including before dispatch, and the server's own next action tells the user a changed pinned config requires a new task or the upgrade flow.
- [ ] Blob identity collapses to one value across `core.autocrlf` off/input/true, `core.fileMode` off with the executable bit set, and the `core.symlinks=false` mode-`120000` case, with the attributes rule in force; the `-text`-absent contrast is recorded rather than asserted as a collapse. The filtered path of the projected-bytes reader is covered.
- [ ] Every secret-rejection propagation path returns `SECRET_DETECTED` with no durable write; the scanner-unavailable branch is covered; retrying the same intent reruns preparation, rejects again, and leaves state, receipt, retained result, and projections unchanged; and a cut before the scan leaves no partial projection.
- [ ] Retention reachability is proven from checkpoint, receipt, and evidence roots, `maintain` records its prune, and the accounting accumulator is proven over more than one retained result.
- [ ] Binary, mode, rename, delete, and symlink restore are collision-safe, including across a real `SIGKILL` in a projection write; legacy staging rejects collisions, cross-repository sources, and secret-bearing sources, and an interrupted staging leaves inert bytes with no state.
- [ ] No malformed, partial, stale, replayed, wrong-task, wrong-digest, or wrong-ID decision resolves a gate, and one shared postcondition proves revision, approvals, and receipt unchanged in every refused case. Path and cross-task attacks are refused at the handler entry before any read or dispatch.
- [ ] Server shutdown and MCP cancellation are observed to terminate the reviewer child and every descendant remaining in its process group, and to leave truthful evidence; an interrupted host-configuration replacement leaves the prior file intact, with registration idempotence and unrelated-setting preservation unchanged.
- [ ] The descendant-escape cell is observed once and recorded unsupported rather than left unevaluated. `docs/reliability-security-limitations.md` states each accepted-unsupported cell plainly. No permanent test asserts a security canary is readable or a descendant escapes.
- [ ] No new MCP tool, gate kind, error code, runtime dependency, durable schema field, or workflow-graph change is added; the crash-control policy test's source scan passes unchanged.
- [ ] Full typecheck, unit, integration, contract, MCP-runtime, build, dependency, notice, release-integrity, and release-reproduction checks pass after explicit bundle risk re-acceptance.

Sequence the two source fixes as develop-then-verify, not as durable tests. Temporarily revert each fix, observe the failure, restore it, observe the pass, and record both observations in the implementation log. If they are, say so in the log and the limitations document and change no source. If they are not, stop and raise it rather than redesigning the termination path inside this phase.

For the crash work, assert on both sides of every cut: the state a reader observes and the absence of any promoted prepared material. The three children's existing assertions must pass unchanged before new cuts are added, since each keeps its own kill helper and only the cut-name list is shared.
