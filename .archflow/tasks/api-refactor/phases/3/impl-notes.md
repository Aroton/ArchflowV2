## Implementation Log: Phase 3 - Client-Driven Phase Implementation

### Decisions Made

- The public commit block in `WorkflowViewV1` carries plural `paths` (sorted, non-empty, schema-enforced) with `requires_human_confirmation`; design milestones project one path with `false`, implementation commits project the exact sorted authorized set with `true` and a two-step client instruction (stage exactly the authorized paths, show the staged diff and exact message for explicit confirmation, commit, then read-only status for observation). Missing commit authority maps to `blocked / inspect`, never invented facts.
- `semanticInvocationEnabled` admits `archflow-phase-impl` with `intent: "resume"`; the apply-side fence in `handleSemanticApply` and the "supported legacy skill workflow" detail suffixes are gone.
- Submission-shape validation runs in `planSemanticAction` before composition (`assertWorkResultFactsMatchPosition`): a succeeded `work-result` must carry `implementation` facts at a `phase-impl` position and must refuse them at document positions. Both directions return `SEMANTIC_SUBMISSION_MISMATCH` failures with the fresh safe view instead of composer `TypeError` crashes.
- The journey harness is shared: `test/helpers/semantic-journeys.ts` extracts the connection/parity harness, the scripted counter-review child, and `reachImplementationHandoff` (drives PRD → design with N phases → phase-design 1 → owned phase-impl hand-off); `semantic-document-journeys.test.ts` imports it instead of carrying private copies.
- `composeGate` now composes the `attempts-exhausted` gate when the shared fixed-point assessor (`assessCurrentEvidence`, the same call status makes, including config `max_attempts` and `currentApprovedUpstreams`) reports the budget spent, before any phase-default kind; an assessor disagreement refuses composition (`gate-fixed-point-disagreement`) rather than composing a gate the fixed point did not advertise.
- `deriveArchiveEnrichments` no longer classifies a readable, authenticated gate archive that does not bind to the current position as an invalid pending waiver origin: such an archive was consumed and superseded by the planning restart an amend-upstream settlement performs, and treating it as invalid wedged the reopened boundary behind an unresolvable inspection. The classification is split by predicate (`archiveAuthenticates` vs `archiveBinds` in `src/state/semantic-status.ts`): archives that are unreadable, or whose request and decision fail `validateDurableSemantics` cross-binding (corrupt or forged bytes), keep the conservative invalid classification; only a semantically valid pair bound to a superseded position yields the empty enrichment.
- `skills/archflow-phase-impl/SKILL.md` was rewritten onto the semantic surface (Section 4.7 of the phase design); `archflow-design` and `archflow-phase-design` staging wording moved to plural `commit.paths` in the same change as the field rename, and their contract pins with them.
- Same-side review remediation: the composer's fixed-point assessment originally omitted the review predecessor, so after a one-hop simple-classified revision the composer could disagree with the advertised action and open the phase-default gate. The predecessor derivation is now one shared helper (`currentReviewPredecessor` in `src/state/status.ts`) used by both the status projection and `composeGate`, making the composer/status agreement mechanically exact.
- Counter-review remediation (all three advisory findings accepted): (1) the supersession fix originally keyed off the combined `archiveBinds` predicate, silently swallowing semantically invalid request/decision cross-bindings along with superseded positions — split per the decision above, with a regression journey that tampers an archived decision into a canonically rendered but cross-binding-invalid pair and pins the invalid classification; (2) reworded the stale document-phase-only ownership sentence in `docs/OVERVIEW.md`; (3) re-ran release regeneration and the full check against the final post-remediation bytes and transcribed that run (see Verification Evidence).
- Commit-gate ordering remediation: opening the commit-authorization gate exposed a pre-existing latent contract defect (landed 2026-08-16, before this phase) — `src/contracts/gates.ts` required `localeCompare` ordering for the authorized path set while every other sorted-path contract and the composer use code-unit ordering. This phase's outputs are the first with a mixed-case path boundary (`docs/COMPLEXITY.md` vs `docs/cli/COMMANDS.md`) where the two orders disagree, so the gate could not open on its own composed context. The gate context now requires the shared code-unit ordering, pinned both directions in `test/unit/gates.test.ts`.

### Deviations from Plan

- Two defects the new journeys exposed required source fixes beyond the phase design's listed corrections (both are fence/ownership-class corrections the design explicitly anticipates in Section 4.6: "any fence/ownership corrections the journeys expose"):
  1. The `attempts-exhausted` gate was unreachable through the semantic surface: status advertised it, but `composeGate` derived the kind from the phase alone and opened `commit-authorization`. The legacy path had opened it through the status prefill template (`request-templates.ts`), which the semantic composer never consults. Fixed by sharing the fixed-point assessor (above).
  2. `update-earlier-work` on material drift wedged every later status at `blocked / inspect` ("pending waiver origin is stale or unauthenticated") because the settle-and-restart left a last-transition archive bound to the superseded position. Fixed in `deriveArchiveEnrichments` (above).
- The phase design's Section 5.1 asked for a parent-design correction (commit sketch `path` → `paths` in `.archflow/tasks/api-refactor/design.md` Section 4.1); the committed parent design already sketches the plural form, so no edit was required.
- One pre-existing core limitation is now exposed and documented rather than fixed in this phase (see Gotchas): after a one-hop simple-classified revision that retains an accepted review finding, the fixed point demands a re-triage the fixed pipeline has no `produce-succeeded → triage` edge for, so the offered triage action is unexecutable (`TRANSITION_INVALID`). The exhaustion gate itself, its settlements, and the significant-classification path all work; the wedge is specific to the simple-revision hop with a retained accepted finding and predates the semantic migration (the legacy composer hit the same refusal). `docs/LIMITATIONS.md` records it; the regression test in `semantic-implementation-completion-journeys.test.ts` stops at that boundary with the exact error documented in place.
- A stale, already-consumed offer carrying a submission is refused as `SEMANTIC_SUBMISSION_MISMATCH` (submission shape is validated before the offer-token comparison in `planSemanticAction`) rather than `SEMANTIC_OFFER_STALE`. Both fail closed, non-retryable, with the fresh view and zero mutation; tests pin the no-submission stale probe for the `SEMANTIC_OFFER_STALE` code.

### Patterns Established

- The gate a composer builds must be derived from the same fixed-point assessment the status projection advertises, never from the phase alone — otherwise the semantic surface can open a gate the workflow never offered. `currentApprovedUpstreams` is now exported from `status.ts` for exactly this shared use.
- A readable archive that no longer binds to the current durable position is a consumed artifact, not an invalid one: "invalid" is for archives that cannot be authenticated at all, and misclassifying superseded authority wedges reopened boundaries.
- Journey drivers belong in `test/helpers/semantic-journeys.ts`: any test that needs a task at an implementation position reuses `reachImplementationHandoff` instead of re-walking the document tiers.

### Gotchas

- The review-stub child script is a generated `#!/usr/bin/env node` program; a single mismatched quote in the generator's template literal produces a `SyntaxError` that surfaces only as `CLI_VERSION_UNSUPPORTED: version "unrecognized"` — inspect the generated file, not the dispatch code.
- The scripted child consumes one findings list per dispatch and repeats the last: the hand-off driver consumes three finding-free dispatches, so impl-tier findings lists must be prefixed with three `[[]]` entries.
- A planning restart purges the runtime verification-transcript cache (`.archflow/runtime/...`); tests that assert worktree bytes across a reopen must not assert transcript bytes there.
- The finishing non-final implementation invocation's `start-next-skill` report carries no `expected_submission` (only offered actions do) — pin `offer === undefined` instead.
- Attempt semantics: rejecting a blocking finding does not re-run review — it advances directly; only accepted findings (or undispositioned blockers) drive remediation re-entry, so the exhaustion loop is acceptance-driven. The attempt ceiling is `DEFAULT_MAX_ATTEMPTS` (3) unless config sets `max_attempts`.
- Known limitation (pre-existing, now documented in `docs/LIMITATIONS.md`): a one-hop simple-classified revision that retains an accepted finding lands at `produce-succeeded` where the fixed point offers a `triage` action the pipeline cannot execute (`TRANSITION_INVALID: produce-succeeded → triage-succeeded`). Classifying such a revision `significant` instead resets the review and works; do not classify a revision `simple` while an accepted finding's revision intent remains unconsummated.
