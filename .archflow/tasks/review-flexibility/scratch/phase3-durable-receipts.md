## 1. Settlement seam for receipt writes

- Kernel: `src/state/transaction.ts` — `runStateTransaction` (1231) wraps everything in the task lock; `executeLocked` (1164) reads state, replays or calls the tool handler's `prepare` callback; `buildPlan` (777) stamps `resultingRevision`, runs `assertPreserved` (319: task/config/workflow/constitution/repository pins + open_gate/approvals/waivers/restart_history preservation), applies commit-time `withLastSeenConfig` normalization (800), embeds the full next state into `IntentReceiptV1.prepared_state`, and `installPlan` (1012) writes result installations → intent receipt (exclusive create) → `state.json` replace (arbitration on races). Config is read in `liveIdentification` (397) via `dependencies.read_config`; the parsed snapshot (`LiveConfigSnapshot{bytes,digest,parsed}` from `src/state/read.ts`) is the natural source for a receipt's "config digest at evaluation" — `state.config_digest` is creation-time-only (`computePinnedConfigDigest`, src/contracts/fingerprints.ts:384, never compared to live).
- Transition planner: `src/state/transitions.ts` `planStateTransition` (425) is pure; draft assembly at 530-545 shows the precedent for optional history fields (`human_revision_history`, `pending_human_revision`, `planned_final_phase` — conditionally spread, never null). A receipts write belongs exactly there: new optional `TransitionPlanInput` field (pattern of `completion_subject_digest`/`authenticated_gate_approvals` at 37-64), appended to the draft like `restart_history` (sorted-set, frozen).
- Flow today: counter-review result commits via `planCounterReviewCommit` (src/review/counter-review.ts:174-249, calls `planStateTransition` targeting `counter_review`-succeeded); triage records via the `archflow_state` handler (src/mcp/handlers/state.ts:518 calls `planStateTransition`); then the human gate opens via `openDurableGate` (src/state/gates.ts:165; writes `open_gate` through `stateWithOpen` + `withLastSeenConfig` at gates.ts:430-462 — its own atomic write, not the kernel); the decision settles via `settleDirectSemanticGateDecision` (gates.ts:1268) / `resolveDurableGate` (1473). The approval-gate composition decision (which gate kind opens, or none) is `composeGate` in src/state/request-composition.ts:509-731 — gate kind derived from phase kind at 547-552; the `archflow_state` handler's approval-loading blocks (`artifactPhaseExitSignal` state.ts:387-430, `completionSignal` 431-461, `legacyJumpSignal` 463-517) are where "no rule matched → no gate" is decided and where receipt facts enter the settling transaction.
- Machinery requiring approved upstreams: `currentApprovedUpstreams` (src/state/status.ts:487-528), `loadProduceUpstreamSubject` (src/state/produce-subject.ts:82-119 owner filter), `hasAuthenticatedArtifactApproval` (transitions.ts:197). `assertPreserved` keeps permitting optional-field appends (it does not touch unknown optional fields).

- Definition file: `src/contracts/durable-state.ts` (not `durable.ts`). `TaskStateV1` type alias at 253-310; Zod mirror `taskStateV1Schema` at 567-622 (`.strict()`, sorted-set `.refine(isSortedUniqueBy(...))` on arrays, `.optional()` for absence, `superRefine` revision-bounds checks).

## 3. Schema generation — impacts + registration

`npm run generate:schemas` = `scripts/generate-schemas.mjs`: esbuild-bundles `src/contracts/internal/schema-generation.ts`, calls `renderGeneratedSchemaFiles()`, writes `src/contracts/schemas/v1/*.schema.json`. `npm run check:schemas` is the byte-exact fence. Groups: leaf (`schema-generation-leaf.ts`), durable (`schema-generation-durable.ts`), gate, errors, mcp-tools, semantic-workflow.
- (a) config gains `approval_rules`: edit `configV1Schema` in src/contracts/config.ts; regenerated `config.schema.json` (leaf group, document at schema-generation-leaf.ts:122-132) and `task-state.schema.json` `$defs/configSnapshot` (the clone mirrors `taskConfigSnapshotV1Schema` re-derive from `configV1Schema` — automatic, but byte-drifts the emitted schema). `TaskConfigSnapshot`/`AbsentIsAbsence` handle the shape automatically. Config change notice paths (`approval_rules.N.…`) flow through the existing generic `ConfigChangeEntry`.
- (b) TaskStateV1 gains receipts: regenerates `task-state.schema.json` (new `$def` if added to the `defs` map in schema-generation-durable.ts:97-118) and — because `IntentReceiptV1.prepared_state` is the full `taskStateV1Schema` (src/contracts/durable-intent.ts:80) — `intent-receipt.schema.json` only refs it. Receipt bytes ride the 1 MiB `MAX_RECEIPT_BYTES` cap (transaction.ts:82) and the `openGateFrozenStateDigest` computation.
- (c) new contract module: create e.g. `src/contracts/durable-rule-receipt.ts` (type aliases + Zod), add an `SCHEMA_IDS` entry in `src/contracts/versions.ts`, register a `SchemaDocumentPlan` in the durable group (`schema-generation-durable.ts` documents list), export from `src/contracts/index.ts` barrel, then generate:schemas.
- Input fingerprint unaffected by config since phase 1 removed config from the composition (src/state/fingerprint.ts:137-160; legacy fallback folds `state.config_digest` back in).

## 6. Evidence-results / retained graph / authority layout — confirmations

- `src/state/evidence-results.ts` prepares/loads review/triage/adjudication result manifests keyed off `state.authoritative_results`; `RetainedEvidenceSet` is per-step. `src/state/retained-result-graph.ts` (27 lines) computes the retained root graph from `authoritative_results` + pending_human_revision + human_revision_history + restart_history — digests only, deduped by result_digest.
- Receipts need no interaction with either: they name subject/rule/config digests, not result manifests; they neither join `retainedResultReferences` nor affect snapshot byte accounting. Only if a receipt ever referenced a result digest would it belong in that root walk.
- Receipts belong in `state.json` only. Authority tree is per-gate/per-result on disk: `.archflow/tasks/<task>/authority/decisions/<gate_id>/{request.json,decision.json}` (claims `gateRequestClaim`/`gateDecisionClaim`, src/repository/paths.ts:108-118), `authority/initialization.json`, `authority/results/<digest>.json`; runtime mirrors under `.archflow/runtime/tasks/<task>/` (intents in `transient/intents/`, payload cache in `cache/results/<digest>/payload/`) — all laid out in src/state/layout.ts. State-embedded optional collections (`baseline_adoptions`, `restart_history`, `human_revision_history`) are the exact precedent: state-only, no authority files.
